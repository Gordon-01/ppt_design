# PPT 美化术（模板内容器系统）

> 客户说"简单一点"，意思是"不要花哨"，不是"少改动"。
> 他们真正抱怨的几乎总是：**空旷**。图片页不空（实体填满），文字页空（文字悬浮）。
> 解法不是加内容、不是放大字体，是**给文字套上容器、建立层级**。

## Phase 0: 侦查（先看后动，禁止跳过）

### 0.1 备份 + 渲染现状

- 永远在**副本**上干活，原始文件只读。
- Windows + PowerPoint 环境：用 COM 导出目标页 PNG（1600×900），**亲眼看**当前状态再动手。
- python-pptx 无法渲染，任何"应该没问题"的想象都不算数。

```python
import win32com.client, os
app = win32com.client.Dispatch('PowerPoint.Application')
pres = app.Presentations.Open(os.path.abspath('副本.pptx'), WithWindow=False)
pres.Slides(12).Export(os.path.abspath('_render/s12.png'), 'PNG', 1600, 900)
pres.Close(); app.Quit()
```

### 0.2 形状清单

逐页 dump：`id / 类型 / 名称 / 位置 / 尺寸 / 文字`。这张清单是后续一切删除、替换、对齐的依据。

```python
from pptx import Presentation
from pptx.util import Emu
p = Presentation('副本.pptx')
for s in p.slides[11].shapes:   # 递归 GROUP
    t = s.text_frame.text if s.has_text_frame else ''
    print(f'id={s.shape_id} type={s.shape_type} name={s.name!r} '
          f'pos=({Emu(s.left).inches:.2f},{Emu(s.top).inches:.2f}) '
          f'size=({Emu(s.width).inches:.2f}x{Emu(s.height).inches:.2f}) text={t[:80]!r}')
```

### 0.3 侦查清单（每页过一遍）

- [ ] 模板骨架是什么：页眉/标题条/logo/页脚/装饰母题（三角形、色块、线）
- [ ] 品牌色是什么：从标题字、标题条填充取色（如 C00000 / FF0000），全片只用这套 + 中性灰
- [ ] 哪些是主题残留缺陷：继承的默认描边（常见为蓝边）、错位图片、文字重叠
- [ ] 哪些是模板垃圾：占位废文案（同一词反复出现）、模板水印、无意义装饰图
- [ ] 哪些页不要碰：封面、目录、章节标题页、带品牌横幅的感谢页
- [ ] 内容栏边界：多数模板有固定内容列（如 0.45"→11.19"），且页脚 logo 占右下角——**卡片宽度到内容列右缘为止，不许压页脚**

## Phase 1: 判级（客户要的是哪一档）

三级美化，按客户反馈逐级升级，**不要一步到位**：

| 级别 | 动作 | 客户观感 | 何时用 |
|------|------|---------|--------|
| L1 修硬伤 | 去继承描边、图片对齐、消重叠 | "就这？" | 仅当委托方明确说"只修问题" |
| **L2 容器系统** | 白卡+角标+标题+分隔线+说明 | "页面饱满了" ✅实证（客户认可档） | **默认档** |
| L3 内容强调 | 关键事实标红加粗、图片加图注 | 再上一个台阶 | L2 交付后客户仍觉得平 |

✅实证：本项目 L1 交付被评价"过于简单"，L2 交付通过。L2 是性价比最高的一档。

### 客户话术解码表 ✅实证

| 客户说 | 实际含义 | 动作 |
|--------|---------|------|
| "简单一点/不要太花哨" | 禁止新颜色、艺术字、复杂图形；**允许**结构化容器 | 上 L2 |
| "太空旷/显空/图片页就不空" | 文字页缺容器和层级 | 上 L2，勿加内容勿放字体 |
| "不能照抄参考图" | 学它的**布局逻辑**（容器+角标+层级），换掉造型和颜色 | 见 Phase 2.4 |
| "一定要保持统一风格" | 同一系统跨页复用；字号全片一致 | Phase 2.5 |
| "不能局部放大字体" | 用卡片高度和留白分布填空间，字号一个不动 | 硬约束 |

## Phase 2: 容器系统（L2 标准件库）✅全部实证

### 2.1 建议条目卡（本 skill 的核心件）

```
┌──────────────────────────────────────────────┐
│ (1) 自查自纠  │  市场团队自查自纠，及时淘汰劣迹业务员      │
└──────────────────────────────────────────────┘
  ↑白卡+轻阴影     ↑竖分隔线(1px, E8E8E8)   ↑正文14pt深灰,左对齐
  ↑红圆角数字块     ↑标题15pt粗体品牌红
```

- **白卡**：填充 FFFFFF、无边框、外阴影（blur 7pt / 距离 2pt / 黑 12% 透明度）。直角，不要圆角。
- **角标**：品牌色圆角方块（圆角系数 0.22）+ 白色粗体序号 16pt。**序号必须来自原文自带的编号**（原稿就写着"1. 2. 3."），这是"内容自带的结构元素"，不是外来装饰。
- **布局**：角标+标题占左侧固定 2.32"，竖分隔线，正文占右侧全部剩余宽度——正文短时也不会留下半边空白。
- 对齐：标题、正文一律 `PP_ALIGN.LEFT`（autoshape 文字默认居中，必须显式改左，✅踩过）。
- 锚点：1-2 行正文用 `MSO_ANCHOR.MIDDLE`；多段长文用 `TOP`，且卡片高度按行数算出来。

### 2.2 问题点卡 / 陈述卡

同款白卡，左侧标记换成**模板自己的装饰母题**（如页眉的小三角旋转 90°），角标数字留给"建议/条目"专用。这样两类卡片语义分明且都不引入外来图形。

### 2.3 几何参数（13.33×7.5 画布，✅实证可直接抄）

| 项 | 值 |
|----|----|
| 内容列 | x=0.45，宽 10.74（右缘 11.19，让开页脚 logo） |
| 横排单行卡 | 高 0.7–0.86，行距 0.06–0.1 |
| 横排双行卡 | 高 1.1–1.35，行距 0.15–0.32 |
| 问题卡(2行正文) | 高 0.9–1.0；3行正文 1.2 |
| 卡片底缘 | ≤ 7.25（页底留 ≥0.25） |
| 标题条到内容 | 问题卡 y=3.12 起，"改善建议："标题行 0.4 |

### 2.4 参考图翻译法 ✅实证（差点翻车的地方）

客户给参考截图时，拆成**结构层**和**造型层**：
- 结构层（要学）：通栏卡片、左侧色块角标、加粗短标题、说明文字、卡片留白节奏。
- 造型层（必须换）：角标的图形（人家是方块箭头）、颜色（人家是蓝）、字体。
- 换造型的安全顺序：① 原文自带元素（编号、项目符号）② 模板自带母题（页眉三角、色块形状）③ 品牌色的几何变体。**绝不复刻参考图的图形。**
- ✅教训：第一版照搬了参考图的 chevron 箭头角标，客户原话"有点完全在抄的感觉"。换成"原文编号数字块"后通过。

### 2.5 跨页一致性 ✅实证（客户的头号要求）

- 所有新卡片由**同一组构建函数**生成（见 cookbook），参数只有位置和行数。
- 字号全片锁死：卡标题 15pt、正文 14pt、区块标题 16pt。任何页面不许单独放大字体。
- 同构页面（问题+建议）布局坐标复用同一套 cfg；页面类型不同（如图文页、纯文字页）时保持元素语言一致即可，不必强行同布局。

### 2.6 该删的东西

- 主题残留：继承的默认形状描边（蓝边）→ `line.fill.background()`。
- 模板垃圾：占位废文案（如同一标签出现3次的"目标分解"）、模板水印名 → 连同其装饰图一起删。
- 脱离品牌色的图表装饰：蓝橙灰黄渐变平行四边形之类 → 整体重建成卡片，**文案一条不丢**。

## Phase 3: 施工纪律

1. **先取文再删形**：删任何形状前，把它的文字完整提取出来（必要时从原始文件重新提取——✅踩过：重建时误删正文，靠原始文件救回）。
2. **短标题从原文提炼**：4字动宾短语（如"提前备货"），红色加粗；正文原文照搬，最多补句号。
3. **删除用签名匹配**：`几何类型 + 填充色 + 是否含文字` 组合判断，不要用 `shape.shape_type` 判断具体图形（见 cookbook 坑1）。
4. **改完必渲染必逐页看图**：脚本打印 success 不算数，异常被吞、静默空跑都发生过（✅两次）。渲染后逐页检查：残影/漏删、文字出卡、重叠、角标编号顺序、旧元素清干净。
5. **交付前自检清单**：每页渲染图看过 → 无残影 → 文字都在卡内 → 编号连续 → 文件能重新打开 → （顺手）错别字/半角标点/目录与章节页标题一致性。

## Phase 4: 文件操作纪律（Windows 实战）✅全部踩过

| 情形 | 处理 |
|------|------|
| 目录里出现 `~$xxx.pptx` | 文件正被 PowerPoint 打开。**不要杀进程**。存临时文件，`mv -f` 覆盖 + 重试循环（sleep 10，6次） |
| 保存报 PermissionError | 同上；也可能是只读属性，`chmod +w` |
| 只读不阻塞交付 | 先存 `_tmp.pptx` 并告知用户当前进度 |

## ❌ 反模式黑名单（每条都付过学费）

| # | 反模式 | 后果 / 正解 |
|---|--------|------------|
| 1 | 用 `shape.shape_type` 判断图形种类 | 它返回 MSO_SHAPE_TYPE（AUTO_SHAPE），永远匹配不上，**静默空跑**。用 `prstGeom/@prst` |
| 2 | 批量清理函数里 try/except 吞异常 | 空跑也不报错。清理后必须 dump 清单 + 渲染验证数量 |
| 3 | 把"少改动"当"简单" | 客户要的是"不花哨"且"饱满"。L1 交付会被打回 |
| 4 | 照搬参考图的图形/颜色 | "完全在抄"。学结构，换造型，用原文/模板自带元素 |
| 5 | 新建 autoshape 不设左对齐 | 文字莫名居中。显式 `PP_ALIGN.LEFT` |
| 6 | 卡片宽度压到页脚 logo 区 | 模板页脚在右下角，内容列右缘止步于它 |
| 7 | 靠放大字体填空白 | 客户明令禁止；用卡片高度和行距分布解决 |
| 8 | 动模板骨架（页眉/标题条/logo/页脚） | 一概不动；只处理页内内容区 |
| 9 | 脚本成功就当改好了 | 渲染 + 逐页看图是唯一验收 |
| 10 | 在原始文件上直接改 | 永远副本干活 |
